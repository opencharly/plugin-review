# 2026.255.1218 — review: AI_REVIEW_MAX_ATTEMPTS knob, fail-hard single attempt

## Summary

Sources the review agent-loop attempt count from a new `AI_REVIEW_MAX_ATTEMPTS` env (default 3 = current behavior; invalid/non-positive values fall back). Setting `1` makes the first failed attempt terminal — fail hard, no repeat cycle. Closes #5.

Three commits, 2 files, +128/−7:
1. `candy/plugin-review/review.go` — `defaultMaxAttempts = 3`, `MaxAttempts` field, env parse (`AI_REVIEW_MAX_ATTEMPTS`), loop uses `cfg.MaxAttempts` with a clamp to 1. The INCONCLUSIVE terminal-marker format is byte-unchanged (only the substituted count varies).
2. `candy/plugin-review/attempt_timeout_test.go` — `TestMaxAttemptsKnob` (default/1/invalid/0) + `TestMaxAttemptsOneFailsFastLive` (env→cfg→loop, request counter = 1) + `TestMaxAttemptsZeroClampsToOne` (directly-constructed `MaxAttempts: 0` → clamp → 1 request).

Context: the loop was `const maxAttempts = 3` (`review.go:347`, removed — see R5 below), so a provider-unanswered review re-runs the whole doomed generation twice more under the per-attempt deadline (45+ min at the old 900s default; live exhibit: opencharly/opencharly run `34688719317`). This knob is what opencharly/.github#98 wires to `1` org-wide, activating on the next charly release weld + TAG bump.
