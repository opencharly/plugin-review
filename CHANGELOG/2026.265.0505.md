# 2026.265.0505 — fix(review): adopt the model vendor's official sampling + guard the residual repetition mode

## Summary

Adopt the **single measured-best model-behaviour default set** for the review engine, defined **once**, and print the resolved sampling so every run shows what was sent.

**The shipped defaults — one configuration, identical in all three surfaces:**

| knob | value |
|---|---|
| `temperature` | `1.0` |
| `top_p` | `0.95` |
| `frequency_penalty` | `0.5` |
| `presence_penalty` | `1.0` |

**Root cause (R1).** The engine sampled at `temperature=0.2`, a near-greedy choice. Once a high-probability token (`Hmm.`) won the argmax it self-reinforced: the model emitted it thousands of times (measured **2,533–38,472×**) and returned no answer — a degenerate-repetition collapse with no verdict. The vendor's official sampling (`1.0`/`0.95`) removes the near-greedy trap; on the longest reviews the sampling alone still left a residual, which the frequency/presence penalties suppress.

**Why all four values, together.** Controlled measurement on the retained runs:

| config | outcome |
|---|---|
| `temperature=1.0`, `top_p=0.95` alone | 16 ok / 1 collapse (17 runs) |
| `+ frequency_penalty=0.5`, `presence_penalty=1.0` | **26 ok / 0 collapse (26 runs)** |

The four-value set is the **one** configuration that measured zero collapses, so it is the shipped default — not the vendor-pure sampling alone. Every value is `AI_REVIEW_*`-overridable, and one env var never silently overrides another: the surfaces carry the same set.

**Observability (new, tested).** The debug request trace now prints the RESOLVED sampling via `samplingTrace(cfg)`, so a bare-environment run proves the defaults applied:

```console
plugin-review[debug]: request — reasoning_effort="high" max_tokens=262144 attempt_timeout=15m0s idle=3m0s sampling=(temperature=1 top_p=0.95 frequency_penalty=0.5 presence_penalty=1) context_bytes=(...) files=N comments=N
```

Temperature always prints a resolved value (`temperatureOrDefault` never returns nil). A genuinely-nil pointer knob (only a bare `Config` leaves `TopP`/`FrequencyPenalty`/`PresencePenalty` nil; `FromEnv` defaults all three) prints as `nil`, so "unset" stays distinguishable from an explicit zero. `TestSamplingTrace` pins both cases.
