# 2026.266.1944 — fix(review): recover an API-omitted per-file patch from the PR .diff

## Summary of changes

The review assembler silently dropped a changed file whose per-file `patch` GitHub omits, rendering it as an **empty** ```diff``` block — so a manifest-scale file (e.g. `charly.yml`) was reviewed as "no change", the validator BLOCKed the PR as *"core diff unverifiable"*, and the auto-close policy then closed it (`opencharly/charly#625`). This recovers such patches from the PR's raw `.diff` and never renders a silent empty block again.

- `candy/plugin-review/ghclient.go` — `files()` now fetches the PR's raw unified diff (`ghkit.Client.PRDiff`, the `.diff` media type, which is NOT subject to the per-file omission) when any file has `NoPatch` with non-zero ±, and fills each omitted patch via `splitUnifiedDiff`. Recovery failure is non-fatal (the renderer marks the file).
- `candy/plugin-review/diffsplit.go` (new) — `splitUnifiedDiff` splits a whole-PR diff into per-file patches keyed by the new-side path; `parseGitDiffPath` handles BOTH header forms git emits — the plain `a/<p> b/<p>` and the C-quoted `"a/<p>" "b/<p>"` (under `core.quotePath` for paths with spaces/tabs/quotes/non-ASCII), via `unquoteGitPath` (reverses `\\`, `\"`, `\t`, `\n`, `\r` and octal `\NNN`) then strips the `b/` prefix so the key equals the API's `filename`.
- `candy/plugin-review/context.go` — `ChangedFile` gains `NoPatch`; `render()` never emits an empty diff block. Its marker **branches on the counts**: a real (+/-) change whose patch could not be recovered says so; a 0/0 rename/binary is described as *"no textual patch … rename or binary change"* and is never asserted to have changed lines.
- `candy/plugin-review/render_test.go` — `TestRenderMarksOmittedPatchExplicitly` covers both the +60/-1697 and the 0/0 case.
- `candy/plugin-review/diffsplit_test.go` (new) — split, rename-key, C-quoted-path, and `unquoteGitPath` escape tests.
- `candy/plugin-review/ghclient_live_test.go` (new) — live-guarded proof against the real `charly#625`.
