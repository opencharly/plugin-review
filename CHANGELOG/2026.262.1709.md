# 2026.262.1709 — refactor(review): the review engine uses the shared sdk/llmkit client (one OpenAI path)

## Summary

The review engine carried its **own** OpenAI-compatible client: `llm.go`, 456
lines of raw `net/http` — a second SSE decoder, tool-delta accumulator, transport
tuning, session-id minting and request builder. The org already has **one** such
client, `sdk/llmkit`, built on the official `openai-go/v3` SDK and used by
`plugin-pipeline` and the `vision:` verb. Two clients is the duplication (R3) that
let the review's copy drift: it POSTed **non-streaming** under a **5-minute
whole-generation deadline**, so the large tool-result turn 2 was killed, twice per
run.

This deletes the duplicate and delegates to `llmkit`. One client, one wire path,
one idle bound.

## Root cause (R1) — the slow eval runs

A 13m49s validator run (`35451451001`, 2026-09-19) logged, verbatim:

```
plugin-review: turn 1: 4 tool call(s)
plugin-review: turn request attempt 1/3 failed: LLM request exceeded the 5m0s whole-request deadline: context deadline exceeded
plugin-review: turn 2: 2 tool call(s)
plugin-review: turn request attempt 1/3 failed: LLM request exceeded the 5m0s whole-request deadline: context deadline exceeded
plugin-review: turn 3: final content len=4758
```

The mechanism: the review's private client had **no streaming** and **no
env-overridable timeout**, so every turn was one non-streaming POST under a fixed
5-minute `http.Client` deadline. Turn 1 is small and fast; turn 2 carries the PR
diff and exceeds 5 minutes → deadline kills it → the per-turn retry re-sends the
same doomed generation (attempt 1/3) → two such stalls ≈ 10 of the 14 minutes.
The org workflow already sets `AI_REVIEW_ATTEMPT_TIMEOUT`, but that knob belongs to
the **newer** engine and does nothing to a client that predates it.

`llmkit` fixes the class structurally, not by tuning a number: it **streams**, and
its only time bound is an **idle** watchdog (silence between chunks), not a
whole-generation deadline — so a slow-but-progressing turn is never cut off while a
dead provider still fails in bounded time.

## What changed

- **`llm.go` 456 → 118 lines.** It now maps `reviewConfig` onto `llmkit.Config`
  and the four review tools onto SDK tool schemas. No `net/http`, no SSE scanner,
  no tool-delta accumulator, no whole-generation deadline.
- **`review.go`** uses `llmkit.Message`/`ToolCall`; the single retry site
  (`chatTurn`) re-issues the FAILED TURN via `llmkit.Chat`; the pass budget and the
  bounded tool-result payload are unchanged review policy.
- **Removed `AI_REVIEW_ATTEMPT_TIMEOUT`.** `llmkit` has no whole-generation
  deadline, so the knob has no referent. `AI_REVIEW_STREAM_IDLE_TIMEOUT` is the
  single time bound.
- **Session affinity minted once per RUN** (`reviewConfig.SessionID`), not once
  per pass — a real bug the cutover introduced and the tests caught: the default
  `MaxAttempts` is 3, so a per-pass mint would send a different session id on each
  pass and defeat the routing the header exists for.
- **Removed clunky stdlib reimplementations:** `parseInt` → `strconv.Atoi`,
  `sortStrings` → `sort.Strings`, `randAlpha` → `crypto/rand`, `splitRepo` →
  `strings.Cut`, and the `stringsReader`/`lookupEnv` indirection files.
- **Tests:** deleted the client-internal suites (`stream_test`,
  `live_gateway_test`, `opencode_session_test`, `attempt_timeout_test`) — that
  contract is `llmkit`'s and is tested there. Added `review_test.go` for the
  gate's OWN contract: knob parsing, pass/turn budget, the retry-the-failed-turn
  policy, the bounded tool payload, the inconclusive class, session stability, and
  the `llmConfig` mapping.
- **Pins:** `sdk` → `v0.2026260.1434` (the release carrying `llmkit`); `spec` →
  `v0.2026259.2033`; `openai-go/v3` added.

The suite exercises the real streaming path end to end: `TestReviewE2E` drives the

and `TestSessionIDStableAcrossPasses` pin one session id per run.
