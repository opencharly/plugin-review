# 2026.271.0909 — fix(review): bound the assembled comment thread (the measured 80%-of-context collapse)

## Summary

Bound the **assembled comment thread** in the review context so it can never dominate the model input.

**The measured defect.** `context.go` assembles ONE user message: PR body + every file patch + commits + **every comment**. On a real failing PR the comment section was **~116 KB of a 146 KB context (80% of the input)**; at that size the model entered a degenerate repetition collapse — `finish_reason="length"`, 460 KB of reasoning, **no verdict**. The SAME review over a thread trimmed to ~30 KB returned `finish_reason="stop"` and a clean `Verdict: PASS` in 71 s.

**The change.**

| File | Change |
|---|---|
| `config.go` | `ThreadMaxBytes` (`AI_REVIEW_CONTEXT_THREAD_MAX_BYTES`), default **48 KiB** (`DefaultThreadMaxBytes`). `0` disables (the one knob whose `0` is meaningful, so it uses the pointer reader). |
| `context.go` | `renderCommentThread`: spends the byte budget **newest-first**, keeps each comment **whole** (never a mid-body slice), and emits an explicit `… N older comments omitted (bodies available on the PR) …` marker rather than dropping silently. WHY documented against the measurement. |
| `charly.yml` | `env_accept` declaration + default `var:`; the public `description:`/skill prose reconciled (R4a) — they said "EVERY comment", now accurate. |
| `render_test.go` | New tests (below). |

The PR body, **every per-file diff**, and the commits are **never** bounded: the prompt reviews every file LINE BY LINE, so only the thread — the one section that grows without bound — is budgeted.

**Relationship to the in-flight sibling.** `opencharly/plugin-review#30` / merged **#31** drops the gate's own machine notices (`## validator INCONCLUSIVE` / `## Auto-closed:`) before assembly. That is a *content* filter; this is a *size* bound. They are complementary and **both** compose: this branch was rebased onto #31 (`origin/main` `1ca7ff6`) and the whole module gate is green with both changes present. Filed as a distinct mechanism (sibling of #30 and #23).
