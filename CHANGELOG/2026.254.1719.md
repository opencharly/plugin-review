# 2026.254.1719 — fix(review): configurable attempt timeout + timeout-class taxonomy (provider-unanswered != BLOCK)

## Summary

RCA-driven root fix for the recurrence of verdict-less validator runs (org gate
died with `context deadline exceeded (Client.Timeout exceeded while awaiting
headers)` — 3 consecutive runs on eval-omarchy #70, once on opencharly #194,
2026-09-11). The formal 8-step root-cause analysis (root-cause-analyzer agent)
identified: the per-attempt HTTP client deadline is HARDCODED at
`5 * time.Minute` (`llm.go` `newLLMClient`) with no env knob; the 3-attempt
loop (`review.go` `runAgentLoop`) has negligible backoff and no
**timeout-class taxonomy**, so a provider latency tail collapses into the same
terminal state as a genuine review BLOCK **minus all its information** (red
check, no verdict, no comment, stale visible verdict).

This PR:

1. **`AI_REVIEW_ATTEMPT_TIMEOUT` env knob** (seconds; default 300 — behavior
   unchanged at default; invalid values fall back) threaded into
   `newLLMClient`'s `http.Client.Timeout` via the existing
   `flag > env > baked default` precedence.
2. **Timeout-class taxonomy**: `isTimeoutClass(err)` (DeadlineExceeded /
   client-timeout strings) per attempt; when ALL attempts die in that class
   the exhausted error is the DISTINCT marker
   `inconclusive: all N attempts timed out — the LLM provider did not respond
   within the attempt timeout (provider unanswered); this is NOT a review
   verdict — re-run the gate`. `candy/plugin-review/attempt_timeout_test.go`
   covers the knob parse and the classification (incl. a behavioral test that
   drives the REAL http.Client through an actual timeout).
3. **gosimple S1002 fix** (commit b79069b): `!= true` → `!` (validator B18).

The verdict logic is UNCHANGED: a BLOCK/PASS still comes only from a produced
Verdict line; the classification only distinguishes the provider-unanswered
exhaustion so callers can branch. Named batch for the rest of the wave
(`G-3d validator-provider-hardening`, separate PRs per repo): the org
workflow's "inconclusive" branch (opencharly/.github), the charly re-pin +
release that ships this plugin version, fallback endpoint/model on
provider-unanswered class, and a model-stability window policy.
