# 2026.271.0852 — fix(review): exclude the gate's OWN machine notices from the next review's context

## Summary

The review engine's context assembler (`candy/plugin-review/ghclient.go` `comments()`, rendered into `<comment_thread>` by `context.go`) fed **every** issue comment back into the next review. But the org `pr-validator` posts **two machine notices** as issue comments about the GATE itself, not about the code:

1. `## validator INCONCLUSIVE — no review verdict was produced …` — its `<details> Diagnostics` tail is ~65 KB of a degenerate `Hmm.` line on an engine decoding collapse;
2. `## Auto-closed: N unanswered BLOCK/INCONCLUSIVE verdicts …`.

Neither carries a review finding. Re-ingesting them is a **feedback loop**: every run appends a fresh multi-KB notice, the next run re-reads all of them, and the growing thread (measured ~176 KB) is itself a driver of the decoding repetition collapse that produces the next INCONCLUSIVE. A trimmed ~30 KB context on the same PR returns a clean verdict.

**Fix.** `comments()` now skips a comment whose body **starts with** either exact header — matched on the comment's first **non-blank, leading-whitespace-trimmed** line (the deterministic marker, *not* the `github-actions[bot]` author). The validator's REAL review comments (`## Review — BLOCK` / `## Review — PASS`) are **kept**: the prompt requires they be dispositioned ("Comment intake"). The human still sees the machine notices intact on the PR.

- `ghclient.go` — `gateNoticeHeaders` + `isGateNotice` + pure `filterGateNotices`; `comments()` applies the filter to the issue-comment stream. Doc comment explains WHY (no finding; the feedback loop drives the collapse).
- `context.go` — corrected the `Comment` doc so it cannot contradict the ONE exclusion.
- `ghclient_test.go` (new) — unit + integration; **FAILS without the filter**.
- `ghclient_live_test.go` — live proof against the REAL `opencharly/plugin-review#26`.

Closes opencharly/plugin-review#30. Producer-first chain: merged tag → charly weld bump (`scripts/host-command-plugins.txt`) → release → `CHARLY_VERSION`. Cross-ref `opencharly/charly#712`.
