# 2026.278.1524 — feat(config): ship AI_REVIEW_MAX_COMPLETION_TOKENS=384000 as a default

## Summary

Ship `AI_REVIEW_MAX_COMPLETION_TOKENS=384000` as a plugin default.

`AI_REVIEW_MAX_COMPLETION_TOKENS` — the answer-only output budget, distinct from the
shared reasoning+answer `AI_REVIEW_MAX_TOKENS` — had **no shipped default**: `config.go`
left `MaxCompletionTokens` nil and the candy's `var:` block omitted it. This makes it an
explicit default on BOTH surfaces the parity test pins:

- `config.go`: new `DefaultMaxCompletionTokens int64 = 384000`, applied in `FromEnv`.
- `candy/plugin-review/charly.yml`: `AI_REVIEW_MAX_COMPLETION_TOKENS: "384000"`.

Making the engine's defaults match the intended configuration means the org no longer
needs to carry the override, and the shipped configuration IS the intended configuration.

**Semantics (measured live on `ollama.com`).** `max_tokens` is the binding cap and
`max_completion_tokens` is ignored there: `max_tokens=10` + `max_completion_tokens=1000`
capped a request at 10 tokens (`finish_reason: "length"`, 0 content bytes), and the
reverse (`max_tokens=1000` + `max_completion_tokens=10`) produced the full 178-token
answer. So on the current provider the new default is inert — it takes effect on a
provider that honours the answer-only budget, where the answer must still have room
after the reasoning. The field stays as designed (set means set; 0 disables),
env-overridable as before.

The Go field doc (`MaxCompletionTokens`) is updated to state the default and the
`0 disables` semantics instead of "Nil when unset".
