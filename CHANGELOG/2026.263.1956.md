# 2026.263.1956 — fix(review): pass the owner/repo slug to ghkit — the bare-name 404 class

## Summary

Fix the engine so every GitHub tool call targets `/repos/<owner>/<repo>/...`. The ghkit adoption in `plugin-review#14` collapsed the `(owner, repo)` pair into **one slug** argument (ghkit owns the path building, R3), but the tool dispatch in `runAgentLoop` kept passing the **bare repo name**:

```go
t.gh.toolFiles(ctx, t.repo, t.pr)   // GET /repos/spec/pulls/140  -> 404
```

Every read-only tool (`get_pr_meta`, `get_pr_body`, `get_pr_files`, `get_pr_file`, `get_pr_commits`, `get_pr_thread`, `get_pr_comment`) therefore 404'd, and the model correctly returned a BLOCK — *"No retrievable PR state"*. This is why `spec#140`, `action-review#7` and umbrella `#231` stayed BLOCKED after the engine weld: the engine became fast (~4.9 s vs the old ~20 min) but could read nothing.

**Measured on the welded engine** (umbrella `#231`, charly `v2026.263.1828`, run `35531666727`):

```
get_pr_meta  -> /repos/opencharly/pulls/231   404
get_pr_body  -> /repos/opencharly/issues/231  404
get_pr_files -> /repos/opencharly/pulls/231/files 404
```

On `spec#140` the bare name `spec` was used: `/repos/spec/pulls/140` 404.

**Fix.** Add `toolSet.slug()` — the ONE place the engine's split `(owner, repo)` meets ghkit's single slug — and resolve it once in `call()`, passing it to all seven dispatch sites. The two other ghkit call sites (`runReviewEngine`'s preflight meta read, `emitReviewEffects`' comment post) already passed `cfg.Repo` (a full slug) and are unchanged.

```go
func (t *toolSet) slug() (string, bool) {
	if t.owner == "" || t.repo == "" {
		return "", false
	}
	return t.owner + "/" + t.repo, true
}
```

An **empty owner is a reported error**, not a silent bare-name path: the review engine's `Repo` is always a full slug (`--repo owner/repo` or `GITHUB_REPOSITORY`), and ghkit cannot build an owner-less `/repos` route. `call()` fails loudly for every GitHub-backed tool when the context is absent, so the fallback cannot re-create the 404 class.

**Why it escaped review.** Every existing tool test is fixture-backed (`t.fixture`), which short-circuits BEFORE the ghkit call, and the live tests skip without a token — so no test ever exercised ghkit's path building. R3's single-GitHub-client refactor changed the argument contract, and no test pinned that contract.
