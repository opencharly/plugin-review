# 2026.270.1323 — refactor(review)!: ONE prompt mechanism (AI_REVIEW_PROMPT) + authorship in the assembled context

## Summary

The review engine's prompt/config surface had THREE overlapping mechanisms and the assembled context dropped the authorship facts a sign-off check needs. This lands a first-principles cleanup plus the authorship fix.

**The problem (live-verified RCA, see opencharly/plugin-review#23):** on a large PR the model can enter a *decoding repetition collapse* (it decides, then loops `Hmm.` forever) and consume the whole shared `max_tokens` budget → `finish_reason="length"`, no verdict, INCONCLUSIVE. Reproduced against the REAL provider at the CURRENT org settings: **1 of 19 full-size runs** (`FAILED after 10m26s`, 592 KB of reasoning, 65,328 × `Hmm.`). Not a transient ollama-cloud hiccup — the mechanism is a decode collapse, not a stall/HTTP error. Separately, the rulebook's ground-rule-3 "operator sign-off" was ambiguous about WHO may sign off, and the engine never received the PR author, so the model oscillated on exactly that ambiguity.

**What this PR changes:**

- **ONE prompt mechanism.** Deleted the `AI_REVIEW_PROMPT_EXTRA` append knob and the duplicate `PromptExtra`/`EffectivePrompt` code path. There is now exactly ONE prompt mechanism: **`AI_REVIEW_PROMPT`** — the FULL rulebook, whose **default** is the GENERIC embedded `prompt.md`. The project's real template (its rules, its designated maintainer logins) lives in the org variable passed to the runner, never in the binary. *(Scope correction, fixing the earlier body's over-broad claim: `REVIEW_PROMPT_PATH` is not part of this repository. It is a workflow env in `opencharly/.github`, has **zero** hits in this repo's tree, and is removed by the sibling PR opencharly/.github#124 — not by this diff.)*
- **The shipped default is fully generic.** `prompt.md` carries only the review *mechanism* (read-only, ONE message, untrusted input, verdict format) plus an authorship section that refers to "designated maintainers" — no project name, no project rules. (`Config.EffectivePrompt` deleted; `review.go` reads `cfg.Prompt`.) Measured: `origin/main` prompt.md **449 lines → HEAD 61 lines**.
- **Authorship in the assembled context.** The PR author is carried (`Opened by: @<author>` — read from the issues response the engine already fetches) and EVERY comment kind — issue, review, inline review — is carried with its **author login**, rendered generically as `### Comment <id> [<kind>] by @<author> at <date>`. No bespoke per-comment path/line fields. The closing instruction now tells the review to weigh EVERY comment by the SAME criteria as the body.
- **Config surface.** `AI_REVIEW_PROMPT` is declared in the candy `charly.yml` `env_accept` (the generic config surface); the `AI_REVIEW_PROMPT_EXTRA` entry is removed. `AI_REVIEW_API_KEY` is removed from `env_accept` and kept ONLY in `secret_accept` (commit `a82b0d1`) — the `charly box validate` defect where one env var appeared in both sections.

Diff: **9 files, +159 / −465** (the generic default replaces the 449-line project rulebook).
