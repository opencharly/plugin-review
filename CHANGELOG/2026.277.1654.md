# 2026.277.1654 — fix(config): an empty AI_REVIEW_REASONING_EFFORT is the default, not "send no effort"

## Summary

`AI_REVIEW_REASONING_EFFORT` was the ONE knob on this plugin's model-behaviour surface read with
`envStrLookup`, which honours an explicitly-set **empty** value. The org validator forwards every
unset org var as `""`, so the declared default `high` (`DefaultReasoningEffort`) never reached the
gate: every request carried `reasoning_effort=""`, and the field comment asserted that this
"disables thinking". It does not — omitting the field leaves Ollama Cloud to apply its own
unbounded default thinking. Measured in the live runs quoted on #36: 61k–88k completion tokens and
a 15m attempt cap, versus 8k–41k at `high`.

Two changes, one commit:

1. **`envStrLookup` is deleted**, and `ReasoningEffort` reads via `envStr`, so an unset **or empty**
   value yields the declared default. The helper had exactly ONE caller in the module.
2. **The false "empty disables" premise is deleted, not reworded** — from the `config.go` field
   comment and from the candy's `var:` description. Both terminal error messages now also report
   the effective `reasoning_effort` and `max_tokens`: the two values an RCA needs, and the two the
   15m run never logged (`review.go` said only "lower `AI_REVIEW_REASONING_EFFORT`" without saying
   what it was).

Plus the test the issue asks for: `AI_REVIEW_REASONING_EFFORT=""` → `DefaultReasoningEffort`.

### A correction to this issue's own premise (R1 — the same defect class)

#36 frames empty-as-unset as "like every other knob". Writing the comment that way would have
re-introduced the exact defect being fixed — a comment asserting a rule the code does not have.
Two readers of this **same** surface deliberately give `""` a meaning:

| reader | what `""` yields | example |
|---|---|---|
| `envStr` (this knob) | **the declared default** | `AI_REVIEW_REASONING_EFFORT=""` → `high` |
| `envBool` | **`false`** | `AI_REVIEW_POST_COMMENT=""` → `false`, although its default is `true` |
| `AI_REVIEW_SESSION_ID` | **affinity disabled** | `sessionID()` reads it with `os.LookupEnv` directly |

The new comment names **both** exceptions instead of claiming a rule the code does not have.
There is **no behaviour change** for those two knobs, and **no `AI_REVIEW_*` env name is added or
removed** — the only env name in the whole diff is `"AI_REVIEW_REASONING_EFFORT"`, which the
manifest already declares, so `TestConfigSurfaceMatchesCharlyYML` (the test that asserts the Go
reader set equals the candy's declared surface) still passes unchanged.

### What is deliberately NOT in this diff

* **`schema/review.cue` — untouched.** Its own header states the `AI_REVIEW_*` configuration surface
  is declared in `charly.yml`'s `env_accept:` list (its single source), and that the schema
  "generates NO `params` package" because the plugin declares no typed `plugin_input`. No env name
  changed, so there is nothing for the schema to express. `config.go` is hand-written, not
  generated: it carries no `// Code generated` header, and the schema header confirms it has no
  Go consumer at all.
* **the `review-skill` entity — untouched.** Its only mention of reasoning is “`AI_REVIEW_DEBUG=1`
  emits the full request trace AND the model's reasoning, which is what an RCA needs.” That states
  no empty-disables premise, so the engine-surface change has no counterpart there.
* **`CHANGELOG/2026.263.0549.md:77` — untouched, deliberately.** It is a *dated record of what that
  release did* (“an empty/zero value disables that knob”), and it is already stale on its own terms
  (the same paragraph says the engine defaults to `reasoning_effort: low`; the default is `high`
  today). Rewriting a past release's changelog would falsify the record, so the false premise is
  deleted only where it describes **current** behaviour.
