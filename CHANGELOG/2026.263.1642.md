## Summary

The review engine's runaway reasoning (measured: 507 KB / 741 KB / 726 KB of
reasoning, `finish_reason: length`, 13–19 min) is caused by delivering a
multi-file unified diff as ONE tool result. This PR delivers the change the way
the model needs it and enforces that the whole change is actually read.

1. **Per-file diff delivery.** `get_pr_diff` is DELETED; the engine adds
   `get_pr_files` (a compact changed-FILE INDEX: path/status/±/patch size) and
   `get_pr_file {path}` (ONE file's full patch, its own message). Nothing is
   truncated.
2. **ghkit adoption (R3).** The hand-rolled `exec.Command("gh")` client is
   deleted; the engine uses the org's canonical GitHub client
   (`github.com/opencharly/plugin-gh/gh`), extended in that repo with per-file
   patches, pagination, and single-comment reads.
3. **Anti-skim guard.** A verdict is REFUSED until every file in the index has
   been fetched via `get_pr_file` — mechanically, not by prompt hope.
4. **Fail-closed context guard.** Input tokens (the provider's REAL count) +
   output reserve + margin over the model's context window is a HARD failure with
   the actionable `inconclusive: PR too large to review in one context` class —
   never a truncation and never a hang.
5. **`high` reasoning by default** (the quality default), `max_tokens` 262144;
   `AI_REVIEW_TEMPERATURE`, `AI_REVIEW_CONTEXT_TOKENS`,
   `AI_REVIEW_CONTEXT_MARGIN` env-configurable. A deterministic empty completion
   fails HARD (no blind retry). A nil-pointer panic in `prFromEventPath`
   (`workflow_dispatch` events) is fixed.
6. **Tests are live-or-skip.** Every service test runs against the REAL model /
   REAL GitHub API and SKIPS when unreachable; the fabricated SSE servers and the
   stub `gh` binary are DELETED. A mock cannot reproduce the spiral — that is why
   the mocked tests stayed green while the real gate failed.

## Root cause (measured, 2026-09-20)

The trigger is the monolithic multi-file diff, NOT size or the token budget:

| payload | reasoning | result |
|---|---|---|
| one consolidated diff (~28 KB) | **507–741 KB** | `finish=length`, 13–19 min |
| same diff split into 2 messages | 500–525 KB | still spirals |
| same diff at the model max (393216) | exhausted | still spirals |
| **the same files delivered PER FILE, `high`** | **580 B** | **verdict in seconds** |
| **the same files per-file, `max`** | **814 B** | verdict in seconds |

So the fix is structural (one file per message), not a bigger budget.
